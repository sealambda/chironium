# Rebuilding the Backend from Scratch

Complete reset workflows for the Elixir backend, with Mix aliases that match our documented steps.

## Reset Levels

| Level               | What it clears                 | VCS Safe? | Use case                           |
| ------------------- | ------------------------------ | --------- | ---------------------------------- |
| **Database only**   | Data in tables                 | ✅ Yes    | Quick data reset, keep schema      |
| **Standard reset**  | `_build/`, `deps/`, database   | ✅ Yes    | Fix compilation issues             |
| **Clean rebuild**   | Above + regenerate TS types    | ✅ Yes    | Daily dev workflow, sync with team |
| **Nuclear rebuild** | Above + migrations + snapshots | ❌ No     | Pre-production migration squashing |

> **Important**: Most developers should use **Clean Rebuild**. Nuclear Rebuild deletes
> VCS-tracked files and should only be used before initial production release.

---

## Quick Reference

### Clean Rebuild (Development) — Safe for Daily Use

Resets your local environment using **committed migrations**. Does not touch VCS-tracked files.

```bash
mix rebuild
```

Or manually:

```bash
rm -rf _build deps client/src/lib/ash.ts && \
  mix deps.get && \
  mix compile && \
  mix ecto.drop && \
  mix ecto.create && \
  mix ecto.migrate && \
  mix ash.codegen
```

### Clean Rebuild (Test)

```bash
mix rebuild.test
```

### Nuclear Rebuild (Regenerate All Migrations)

**⚠️ DANGER: Deletes VCS-tracked migrations and snapshots. Only for pre-production use.**

```bash
mix rebuild.nuke
```

This regenerates all migrations from scratch. Use this **only** when:

- Starting a brand new project with no production data.
- Squashing migrations before initial production release.
- You understand this will cause git to show changes to committed files.

Or manually:

```bash
rm -rf _build deps client/src/lib/ash.ts priv/repo/migrations/* priv/resource_snapshots/* && \
  mix deps.get && \
  mix compile && \
  mix ecto.drop && \
  mix ecto.create && \
  mix ash.codegen initial && \
  mix oban.install && \
  mix ecto.migrate
```

**After nuclear rebuild**, you must commit the new migrations:

```bash
git add priv/repo/migrations/ priv/resource_snapshots/
git commit -m "chore(db): Squash migrations into initial baseline"
```

## Mix Aliases

| Alias              | Description                                  | VCS Safe? |
| ------------------ | -------------------------------------------- | --------- |
| `mix rebuild`      | Clean rebuild for development                | ✅ Yes    |
| `mix rebuild.test` | Clean rebuild for test environment           | ✅ Yes    |
| `mix rebuild.nuke` | Nuclear rebuild (regenerates all migrations) | ❌ No     |

```bash
# Clean rebuild for development (safe, uses committed migrations).
mix rebuild

# Clean rebuild for test environment.
mix rebuild.test

# Nuclear rebuild (DANGER: deletes VCS-tracked files).
mix rebuild.nuke
```

> **Note**: `mix rebuild` and `mix rebuild.test` perform a **Clean Rebuild** — they reset
> your local database and recompile, but do NOT touch VCS-tracked migrations or snapshots.

## Manual Step-by-Step Guide

### 1. Remove Build Artifacts

Remove compiled code and downloaded dependencies:

```bash
rm -rf _build deps
```

**What this does:**

- `_build/` — Contains compiled `.beam` files for all environments (dev, test, prod).
- `deps/` — Contains downloaded Hex packages.

### 2. Remove Generated TypeScript Types

If you're using `ash_typescript` for frontend type generation:

```bash
rm -rf client/src/lib/ash.ts
```

This file is auto-generated by `mix ash.codegen` and should be regenerated after backend changes.

### 3. Drop the Database

Remove the existing database completely:

```bash
# For test environment
MIX_ENV=test mix ecto.drop

# For development environment
mix ecto.drop
```

**Note:** This permanently deletes all data. Make sure you have backups if needed.

### 4. Fetch Dependencies

Download all Hex packages fresh:

```bash
mix deps.get
```

### 5. Compile the Project

Compile all Elixir code:

```bash
mix compile
```

### 6. Create and Migrate Database

Recreate the database with all migrations:

```bash
# For test environment
MIX_ENV=test mix ecto.create
MIX_ENV=test mix ecto.migrate

# For development environment
mix ecto.create
mix ecto.migrate
```

**Shortcut:** Use `mix ecto.reset` to combine drop, create, and migrate:

```bash
MIX_ENV=test mix ecto.reset
```

### 7. Regenerate TypeScript Types

Regenerate the Ash TypeScript hooks for the frontend:

```bash
mix ash.codegen
```

### 8. (Optional) Seed the Database

If you have seed data configured:

```bash
MIX_ENV=test mix run priv/repo/seeds.exs
```

## Additional Cleanup Options

### Why Nuclear Rebuild Exists

The **Nuclear Rebuild** (see Quick Reference) deletes VCS-tracked migrations and snapshots,
then regenerates them from your current Ash resource definitions.

**What these directories contain:**

- `priv/repo/migrations/` — Ecto migration files (SQL schema changes). **Committed to VCS.**
- `priv/resource_snapshots/` — Ash snapshots tracking resource state at each migration. **Committed to VCS.**

**When to use Nuclear Rebuild:**

- Starting a brand new project with no existing data.
- Squashing migrations before initial production release.
- Resource snapshots got badly out of sync (rare).

**When NOT to use Nuclear Rebuild:**

- ❌ You have existing data you need to preserve.
- ❌ The project is already in production.
- ❌ You just want to reset your local database — use **Clean Rebuild** instead.
- ❌ You're collaborating with others who have the current migrations.

> **See also**: [MIGRATIONS.md](../MIGRATIONS.md) for the complete migration workflow guide.

---

### Clear Hex Package Cache

Rarely needed, but useful if you suspect corrupted packages:

```bash
rm -rf ~/.hex/packages
mix local.hex --force
```

### Reset Frontend Dependencies

For a complete frontend rebuild:

```bash
rm -rf client/node_modules client/pnpm-lock.yaml
cd client && pnpm install && cd ..
```

### Clear Dialyzer PLTs

If you're having Dialyzer issues:

```bash
rm -rf _build/dev/*.plt _build/dev/*.plt.hash
```

### Reset Oban Jobs

To clear all background job history, roll back all migrations and re-migrate:

```bash
MIX_ENV=test mix ecto.rollback --all
MIX_ENV=test mix ecto.migrate
```

## Troubleshooting

### Database Connection Refused

Ensure PostgreSQL is running:

```bash
sudo systemctl start postgresql
# or
pg_isready
```

### Compilation Errors After Reset

Try cleaning more aggressively:

```bash
rm -rf _build deps
mix deps.get
mix deps.compile
mix compile
```

### TypeScript Types Out of Sync

Regenerate after any Ash resource changes:

```bash
mix ash.codegen
```

### Test Failures After Reset

Run the precommit checks:

```bash
mix precommit
```

Or run tests directly:

```bash
mix test
```

## Recommended Workflow

For day-to-day development, you typically only need:

```bash
# After pulling new changes
mix deps.get
mix ecto.migrate
mix ash.codegen

# Before running tests
MIX_ENV=test mix ecto.migrate
mix test
```

Use the full reset only when:

- Switching between major branches with schema changes.
- Debugging mysterious compilation or runtime errors.
- Starting fresh after corrupted state.
- Setting up CI/CD pipelines.
