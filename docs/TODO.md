## Public Demo Mode — Implementation Plan

[Plan](public-demo.md).

- **P2: with demo mode off, a `POST /demo` without a CSRF token answers 403, not 404.** The `:browser` pipeline runs `protect_from_forgery` before `DemoController`'s `require_demo_mode` plug, so a probe without a token learns the route exists. The 403 reveals nothing else, and a request with a valid token gets the 404 that D6 expects. Repro: with demo mode off, `POST http://localhost:4000/demo` with no `x-csrf-token` header answers 403; the same request with the token from the `/sign-in` meta tag and its session cookie answers 404. Location: `lib/chironium_web/router.ex:25` (`protect_from_forgery` in `:browser`), `lib/chironium_web/controllers/demo_controller.ex:11`.
- **P2, unconfirmed: the first demo start on a cold server once stayed on `/sign-in`.** In the first 1440px browser run, clicking "Try the demo" right after the page opened left the user on `/sign-in`; no flash text or server log was captured, and it did not recur once the test waited for the page to load. The form posts natively to `/demo` with a CSRF token before LiveView connects, so a missing hydration guard is unlikely; a slow or failed first `Demo.start` (which would show "Couldn't start the demo. Please try again.") is not ruled out. Repro: start a fresh server with `DEMO_MODE=true`, open `/sign-in` and click `sign-in-demo-button` immediately. Location: `lib/chironium_web/live/sign_in_live.ex:266` (demo form), `lib/chironium_web/controllers/demo_controller.ex:36` (`start/1`).
- **P2: on the "Your demo has ended." screen, "Join organization" can never work.** The screen appears after the cleanup has deleted the visitor's user, so the session is anonymous and accepting a valid invite code fails with "could not be found". Fix (needs a product decision): leave the join action out of the demo-ended state, or keep it and sign the visitor into a new demo first. Repro: visitor A starts a demo and invites someone; visitor B starts a demo; age B's organization and user by 25 hours and run `DemoCleanup`; B's app shows "Your demo has ended."; B clicks "Join organization" and enters A's code, and an error toast appears. The global cap still holds, so nothing leaks. Fix: key IPv6 addresses on their /64 prefix. Repro: demo mode on, `starts_per_ip: 1`; `POST /demo` with `x-forwarded-for: 2001:db8:1:1::1` redirects to `/app`; the same with `2001:db8:1:1::2` also redirects to `/app` instead of `/sign-in`.
