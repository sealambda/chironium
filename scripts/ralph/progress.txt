## Codebase Patterns
- Error boundaries should be added to routes using TanStack Router's `errorComponent` property
- The app uses biome for linting (not eslint) - run `pnpm lint` in the assets directory
- Typecheck via `pnpm typecheck` in the assets directory

- API utilities follow a clean pattern: graphql.ts handles all GraphQL requests with centralized auth error handling, request.ts provides header building utilities
- Use `import type { X }` instead of `import { type X }` for type-only imports (biome lint rule)
- Layout follows M3 window size classes: <600px (compact/mobile), 600-839px (medium/tablet), 840px+ (expanded/desktop)
- Navigation configuration lives in shared/layout/nav-items.ts - update there to add new nav items
- Overlay components (dialog, sheet, popover, dropdown-menu) use Base UI; alert-dialog uses Radix UI
- All overlays use z-50 for z-index and Portal for rendering outside the DOM tree
- Import graphql from @/gql (not @/gql/gql) for proper codegen type inference
- pnpm typecheck uses root tsconfig - use `tsc -b --noEmit` to check all project references
- Feature types should live in model/ directory (e.g., customer-types.ts), not in UI components
